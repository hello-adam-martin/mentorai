How to use Mentor

Mentor turns how your business should run into a small set of Markdown files, then makes an AI engine operate inside those rules. This page is the quick orientation — what to open, the order to do things in, and how to put it live.

Open Mentor Studio → Docs & Learn →

1 · The quick path

From nothing to a deployable model in one sitting. You don't need every layer to start — Strategy, Governance, and one agent is a complete first pass.

  1. Open Mentor Studio. It's the all-in-one tool. Everything runs in your browser — nothing is uploaded.
  2. Answer the questions, layer by layer. Studio walks you through each one with plain-English help and pre-fills safe defaults (cautious hard limits, sensible escalations). Fill in what's true for your business.
  3. Review on “Map & validate”. See your whole model as a live map and confirm the validation panel is green. Click any box to inspect its full definition. Fix anything red before moving on.
  4. Hit “Download (ready to run)”. You get one self-contained folder — your seven layers, the launch prompt (AGENTS.md), and the agent skills all inside it, plus a DEPLOY.md that says how to run it.
  5. Put it live on an engine. The download is a self-contained folder — start your engine inside it (with Hermes Agent: cd in and run hermes; it picks up AGENTS.md automatically), then follow the DEPLOY.md. Begin with one agent, everything at recommend — it proposes, you confirm — then widen as it earns trust.

Coming back to a model you saved? In Studio use “Import an existing folder” to re-open it and map, validate, or recompile — no rebuilding.

3 · What you're building

Mentor organises a business into seven layers. Intent flows down; outcomes flow up.

  • 1Strategy — what the business is trying to achieve, as weighted, measurable objectives.
  • 2Governance — what the system may do alone, what needs sign-off, and the lines it never crosses.
  • 3Learning — how it improves: patterns, predictions, simulations.
  • 4Core — the reasoning engine (chosen, not authored).
  • 5Domain agents — the specialists that do the work, each scoped to its allowed actions.
  • 6Operational objects — your real things (customers, jobs, properties…) as living record types.
  • 7Human collaboration — the people who approve, oversee, and step in.
Built around intent — not forms Autonomy is earned — start cautious, loosen on evidence Humans stay in the loop Just Markdown — no lock-in, runs on any engine

4 · Putting it live

The “Download (ready to run)” ZIP is your business folder — self-contained and runnable, with the launch prompt (AGENTS.md) sitting inside it alongside the seven layers.

Start your engine inside the folder. Open a terminal in the unzipped folder and start your engine there — it loads AGENTS.md from the working directory automatically and reads the layers on demand. With Hermes Agent that's literally cd <your-folder> then hermes (then ask it “what are you optimising for?” as a sanity check).

Install the skills. Copy the folder's skills/ into your engine's skills directory (e.g. ~/.hermes/skills/). The DEPLOY.md inside lays out all three steps.

Then start small: one agent, one channel, everything at recommend, watching the decision feed — and promote actions to auto only once they've proven safe. The Playbook walks the whole deployment, and Engine adapters has a complete worked example for Hermes Agent (including a step-by-step play for running on Windows/WSL).

5 · Good to know

Do I need both the folder and the launch prompt?

Yes — and they ship together. The launch prompt (AGENTS.md) only bakes in Strategy and Governance — the things the agent must always have in mind. It reads Operational Objects, Domain agents, Learning, Human Collaboration, and the per-action detail on demand from the folder's files. In the download, the prompt sits inside the folder with the layers, so the folder is the one self-contained thing you run.

How do I edit a model later?

Open Mentor Studio and use “Import an existing folder” to load it. You can re-map, re-validate, and recompile. (The editable folder is also inside the deploy ZIP.)

Which AI engine does it run on?

Any — Mentor is engine-agnostic and entirely Markdown. Engine adapters maps Mentor's abstract capabilities onto a real engine; Hermes Agent is the worked example. Switching engines means swapping the adapter, not rewriting your model.

Is anything uploaded to a server?

No. Studio, Mission Control, and the Dashboard all run entirely in your browser. The CLI runs on your own machine. Nothing leaves your computer.

What do the autonomy tiers mean?

Every action is one of three: auto (do it now, log why), recommend (propose and wait for a yes), or approve (do nothing until a named person signs off). Start cautious — keep risky or irreversible actions behind approve, and promote toward auto only on evidence. Recommended defaults has the safe starting set.

What if validation is red?

The map's validation panel lists exactly what's wrong — objective weights that don't sum to 1, a reference that doesn't resolve, a missing governance piece. Fix those before compiling; a model with dangling references will misbehave when it runs.
